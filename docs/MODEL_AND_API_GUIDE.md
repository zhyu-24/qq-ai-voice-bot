# 模型选择与 API 获取（零基础）

这份指南只处理“机器人怎样生成文字”。QQ 官方机器人负责收发消息，GPT-SoVITS 或其他 TTS 负责生成语音；它们都不是对话大模型的替代品。

## 先看三个必须填写的东西

无论使用哪一家模型服务，AstrBot 通常都需要下面三项：

| 项目 | 它是什么 | 从哪里来 |
| --- | --- | --- |
| Base URL | 模型服务的 API 地址 | 服务商控制台、开通邮件或官方开发文档 |
| API Key | 调用模型的私密凭据，等同于密码 | 服务商控制台的“API 密钥 / 密钥管理” |
| Model ID | 模型的精确机器名，不是宣传名称 | 服务商控制台的模型列表或官方文档 |

不要把 API Key 发进群、截图、写进 README、提交到 Git，或塞进人格包、语音包和基础环境包。若不小心泄露，请立刻到服务商控制台删除或轮换该 Key。

## 我该选什么模型？

对于“QQ群里短句互动 + 角色人格”的默认对话模型，优先级应是：**文本对话能力稳定、回复快、不会把思考过程混进文本**。最简单的选择方法如下：

1. 在你的服务商模型列表里，优先找带有 `Chat`、`Instruct`、`非思考` 等含义的**文本对话模型**。
2. 有 `Thinking`、`R1`、`Reasoning` 一类模型时，把它们留作复杂问题的备用模型；不建议让它们承担每一条群聊回复。它们通常更慢，也可能返回 `<think>` 或单独的推理内容。
3. 不要把 `Embedding`、`Rerank`、`ASR`、`TTS`、`T2I`、`I2V`、`T2V`、图像/视频生成模型选为默认对话模型；这些不是用于普通聊天回复的文本模型。
4. 同一服务商有多个通用对话模型时，先从较快、较经济的一个开始，发送 2～3 条真实中文短消息测试人格表现；效果不满意时再换更强的通用文本模型。价格、可用模型和限额以你账号控制台显示为准。

> 角色感主要由人格提示词、示例对话和上下文决定；把模型换得更大不一定能解决“说话不像角色”。先让默认模型稳定、干净地输出文字，再微调人格包更划算。

## 路线 A：你已经有 API 网关（以并行科技 MaaS 为例）

如果你从公司、学校或聚合网关拿到了模型服务，**只使用该网关创建的 API Key 和模型 ID**。不要把 DeepSeek、Kimi、MiniMax 等别家官网创建的 Key 填进这个网关。

以并行科技 MaaS 为例：登录 [并行科技 AI 平台](https://ai.paratera.com/)，在控制台中寻找“API 密钥”“密钥管理”或类似入口，创建一个名称如 `AstrBot` 的 Key 并立即保存。并行科技公开页面说明其 MaaS 提供 API 密钥管理及多模型服务，但不同账号的菜单、可用模型和 URL 可能不同。

然后在控制台的模型列表中复制**完整、精确的 Model ID**。如果你已经在 AstrBot 中测试成功过某个 Base URL，就保持该地址不动；不要因为别人的教程而自行补上或删掉 `/v1`。网关的 URL 规则、权限和可用模型，应以你的控制台、开通邮件或客服说明为准。

## 路线 B：我从来没有用过 API

可以直接选择一家官方模型平台。以下三家都提供 OpenAI 兼容的文本模型接口，适合在 AstrBot 中通过“OpenAI API 兼容”一类提供商接入：

| 平台 | 创建 Key | 官方快速开始 | 官方示例 Base URL |
| --- | --- | --- | --- |
| DeepSeek | [API Keys](https://platform.deepseek.com/api_keys) | [API 文档](https://api-docs.deepseek.com/) | `https://api.deepseek.com` |
| Kimi | [API Keys](https://platform.kimi.com/console/api-keys) | [快速开始](https://platform.kimi.com/docs/overview) | `https://api.moonshot.cn/v1` |
| MiniMax | [接口密钥](https://platform.minimaxi.com/console/access?tab=api-keys) | [OpenAI SDK 文档](https://platform.minimaxi.com/docs/api-reference/text-openai-api) | `https://api.minimaxi.com/v1` |

通用步骤：

1. 打开其中一个官方平台，注册并完成它要求的实名、余额或计费设置。
2. 进入控制台的 **API Key / 接口密钥** 页面，创建一个新 Key；名称可以写 `AstrBot`。
3. 创建后立即复制并保存到自己的密码管理器。不要把 Key 放进记事本截图或云盘公开链接。
4. 打开该平台的模型列表，挑一个文本对话模型，复制它的精确 Model ID。
5. 记下该平台文档写明的 Base URL、刚创建的 API Key 和 Model ID，再进行下一节的 AstrBot 配置。

不同平台的模型名、计费方式和可用地区会更新；始终优先看你正在使用平台的控制台与官方文档，而不是照抄其他平台的名字。

## 在 AstrBot 里怎么填

1. 打开 `http://localhost:6185/#/providers`，进入 **模型提供商**。
2. 新建与服务商匹配的提供商；若对方文档写“OpenAI 兼容”，选择 AstrBot 中相应的 OpenAI API 兼容类型。
3. 按服务商给出的值填写 **Base URL**、**API Key**、**模型名称 / Model ID**，保存并启用。
4. 若界面有“测试”，先测试；如果没有，就打开 `http://localhost:6185/#/chat` 发送：`只回复：连接成功。`
5. 成功后打开 AstrBot 的 **配置** 页面，将这个模型设为 **默认对话模型**。已有聊天会话可能还在沿用旧模型，新建会话再确认一次。
6. 最后回到 QQ 中 @机器人发送一条短消息。文字正常后，再检查 TTS 是否已启用；语音问题请按本项目的本地语音说明单独排查。

## 常见问题

| 现象 | 优先检查 |
| --- | --- |
| `401` / `403` | API Key 是否复制完整、是否属于当前 Base URL 的服务商、账号是否已开通权限或余额 |
| `404` / 找不到模型 | Base URL 的路径是否照官方文档填写；Model ID 是否从控制台完整复制 |
| `provider not found` | AstrBot 中该提供商是否仍启用；默认对话模型是否仍指向它 |
| 回复带 `<think>` 或很慢 | 换成非思考的文本对话模型；不要把 Thinking/R1 模型当作群聊默认 |
| AstrBot 聊天成功、QQ 仍不回复 | 这是 QQ 接入或平台配置问题，不是 API Key 问题；检查 AstrBot 机器人适配器、QQ WebSocket 和 IP 白名单 |
| 只有文字，没有语音 | 对话模型正常；继续检查 AstrBot 的 TTS 总开关、默认 TTS 提供商和 GPT-SoVITS API |

## 成本和安全小建议

- API 按服务商的 token、套餐或账户规则计费；几十条短群聊回复通常比长文、思考模型或多轮大上下文便宜得多，但具体价格必须以控制台账单为准。
- 初次使用时可设置低额度、消费提醒或每日预算，先观察一两天的实际用量。
- 为机器人单独建一个 API Key；不再使用时删除它，比长期复用个人主 Key 更安全。
- 基础环境包只教人填写自己的 Key，绝不携带任何发布者或使用者的 Key。
